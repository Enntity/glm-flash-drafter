# Contributing

Thanks for helping. This project trains a drafter whose value depends on its
license, so the rules on data and weights are strict.

## Before you open a pull request

- **License.** Contributions are accepted under Apache-2.0 (the repository
  license). By opening a pull request you confirm you have the right to
  contribute the code or text under it.
- **No restricted weights or data.** Do not add, link as a training input, or
  derive anything from `incoai/GLM-5.3-Flash-DFlash2` or other non-commercial /
  no-derivatives checkpoints. Every tensor load goes through
  `enntity_drafter/guard.py`; `tests/test_train.py` fails if a module loads
  tensors any other way.
- **No data in git.** Prompts generated by the builders, teacher generations,
  captures, checkpoints and exports stay out of the repository (`.gitignore`).
  Prompt *builders* are welcome when every string they emit is authored by you
  or comes from a source whose license allows training and redistribution
  (say which in the module docstring and the row `license` field).
- **No private or personal data**, no hostnames, addresses, keys or tokens.
- **Tests.** Add a CPU test for new behaviour. Run the files you touched:
  `OMP_NUM_THREADS=1 python -m unittest discover -s tests -p test_<name>.py -v`.
- **Numbers.** A performance or acceptance claim needs the command, the commit,
  the hardware and the raw output. Report losing cells as well as winning ones,
  and give run-to-run spread when you have it.

## Contributing data or compute

Shared data and training updates are not accepted yet: the checks they need
(see docs/roadmap.md) are not built. If you want to help with that, open an
issue to discuss the design first.

## Style

Keep changes small and consistent with the code around them. Prefer removing
code to adding it. Python 3.10+, standard library where possible.
